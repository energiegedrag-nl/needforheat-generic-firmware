# TODO – needforheat-generic-firmware

Open work for this repository, distilled from the old NeedForHeat Trello board, including the discussions on the cards (paraphrased and regrouped) and from the 2026 maintenance review.

Items that touch several repositories are written out in full in one *lead* repository; the others list them with a link (→). Keep the details up to date in the lead repository only.

## Now: needed to run at home this winter

- [ ] <a id="buffer"></a>**Persistent buffering for at least 24 hours.** Keep every measurement the server has not confirmed in flash (finish the `persistent-buffering` branch, LittleFS/SPIFFS), so that reboots and outages up to 24 h lose nothing; this is a stated requirement of DataGear but was never field-tested. Store values compactly (raw sensor encoding roughly halves the space) and size the RAM queue from measured free heap until then. Earlier attempts stalled on flash space: with OTA slots there was too little room for a SPIFFS partition (release builds helped), and the 2024 branch `feat/persistent-buffering` of the living room firmware hit binary size limits and an unexplained 'formatter not defined' error. Plan the partition layout together with the ESP-IDF upgrade. Also affects: needforheat-server-api. *(Trello #25, #494)*
- [ ] <a id="unsigned"></a>**Release workflow without the Windesheim signing key.** The release workflow assumes a secure-boot signing key that this organisation does not have. Make signing optional so unsigned releases (and OTA images) can be built here. Also affects: needforheat-p1-reader-firmware, needforheat-living-room-module-firmware, needforheat-presence-detector-firmware, needforheat-boiler-monitor-firmware. *(Trello #480)*
- [ ] <a id="actfail"></a>**Recover cleanly when activation fails.** If Wi-Fi provisioning succeeds but activation at the server fails, the device looks provisioned but never uploads. v3.3.0 retries by restarting every 60 s; better: after a few failures, clear the Wi-Fi credentials and show the provisioning QR code again, with a clear message. Also affects: needforheat-living-room-module-firmware. *(Trello #837)*
- [ ] → Allow WPA2/WPA3 networks in the Wi-Fi list — see [needforheat-gearup-app](https://github.com/energiegedrag-nl/needforheat-gearup-app/blob/main/TODO.md#wpa3) *(Trello #806)*

## Soon: robustness and correctness

- [ ] <a id="ota"></a>**Make OTA updates trustworthy and staged.** OTA is implemented but has never been tested end to end. Test it on the P1 reader and living room module first. Then replace the poll of the GitHub API (60 calls/hour per IP, every device updates at once) by an update channel on our own server with staged rollout (a few devices first, then the rest). Expected to be little work for the P1 reader and living room module. Keep a manual step before a release reaches devices (suggestion from the team). Also affects: needforheat-server-api, needforheat-p1-reader-firmware, needforheat-living-room-module-firmware. *(Trello #347, #770)*
- [ ] <a id="idf"></a>**Upgrade to ESP-IDF 5.5 (WPA3, Wi-Fi 6).** The firmware is built on ESP-IDF 4.2, which cannot join WPA3-only or some Wi-Fi 6 networks. Plan and spike results: `docs/22` in the deployment repo (LovyanGFX 1.x, NVS types, OTA config, SNTP and Bluetooth API changes). Real impact: at least one participant dropped out because their network used WPA3 or WPA2-Enterprise, and some phone hotspots were not visible. Also affects: needforheat-gearup-app, needforheat-p1-reader-firmware, needforheat-living-room-module-firmware, needforheat-presence-detector-firmware, needforheat-boiler-monitor-firmware. *(Trello #806)*
- [ ] <a id="skew"></a>**Log clock skew after every NTP sync.** Report how many seconds the clock was corrected at each NTP sync as property `clock_skew` (register it for each device type). Cheap to add and lets the analysis detect and repair bad timestamps. Data from the earlier campaign had 7 uploads dated 1970 and 1390 uploads dated 2036 or later; comparing device time with server time per upload makes such errors detectable. Also affects: needforheat-server-api. *(Trello #471)*
- [ ] <a id="interval"></a>**Find out why some 10-minute series contain 20-minute gaps.** About 3% of the intervals in 10-minute schedules were 20 minutes. Find the cause (scheduler drift, upload blocking measurements, Wi-Fi reconnects) and fix it. *(Trello #412)*
- [ ] <a id="buttons"></a>**Let generic and device-specific code share buttons.** When device firmware uses a button the generic library already registered, presses get lost. Provide one button registry with per-button handlers. Also affects: needforheat-p1-reader-firmware, needforheat-living-room-module-firmware, needforheat-presence-detector-firmware, needforheat-boiler-monitor-firmware. *(Trello #833)*
- [ ] <a id="provint"></a>**Provisioning after a Wi-Fi reset fails if a measurement interrupts it.** On the living room module, provisioning after a Wi-Fi reset can be interrupted by a scheduled measurement; the result is a reboot, an unauthorized device and a misleading 'Info? Scan!' screen. Pause measurements while provisioning. Likely cause (hypothesis): a measurement alarm still set in the RTC after the Wi-Fi reset. Clear the BM8563 alarm (or re-initialise the RTC) when resetting provisioning, then test. Also affects: needforheat-living-room-module-firmware. *(Trello #891)*
- [ ] <a id="einkstatus"></a>**Show device status on the e-ink screen.** After provisioning, show the time of the last measurement and the last successful upload (local time) and, while provisioning, which step the device is in, including failures. Optionally show current values (CO2, temperature, RH, persons; P1 power). Also affects: needforheat-living-room-module-firmware, needforheat-p1-reader-firmware. *(Trello #303, #867, #1218, #499)*
- [ ] <a id="prefix"></a>**Configurable API path prefix; move new firmware to /v3.** All firmware calls `/v2/device/activate` and `/v2/upload`; the reverse proxy maps these to the current (v3) server, whose device protocol is unchanged. Make the prefix a build setting like the host name, let new releases use `/v3`, and drop the proxy alias once no v3.x devices remain. Also affects: needforheat-server-api, needforheat-server-configuration.
- [ ] → Freeze after scanning a device and switching apps — see [needforheat-gearup-app](https://github.com/energiegedrag-nl/needforheat-gearup-app/blob/main/TODO.md#freeze) *(Trello #772)*

## Later: features and ideas

- [ ] <a id="rtcprep"></a>**Set the RTC while preparing devices.** Devices can start measuring before NTP has synced. Set the RTC to UTC right after flashing (for example from the flashing tool), so early measurements get a usable timestamp. v3.3.0 already drops implausible timestamps. The BM8563 RTC has a voltage-low flag that tells whether its time is still valid; use that instead of (or besides) the year check in v3.3.0. *(Trello #402)*
- [ ] <a id="infourl"></a>**Default and server-provided info link on the screen.** API v3 no longer returns `device_type.info_url`; v3.3.0 keeps the built-in default. Decide whether the server should provide the link and text again (per device type or campaign), and make the default point to our own manuals. Decided earlier: the text under the QR code stays language-neutral ('Info? Scan!'); the link first tries a campaign-specific page and falls back to a generic default page that the firmware developer writes. Also affects: needforheat-server-api. *(Trello #470, #835)*
- [ ] <a id="einkfix"></a>**E-ink screen glitches.** Speed up drawing multi-line menus (off-screen buffer); fix text shifting up after a menu times out; keep the screen readable after power loss instead of going white or dim; honour the 4-module quiet zone around QR codes; check whether `epd_fast` is still needed with LovyanGFX 1.x. Known remedy for fading: switch the e-paper charge pump (HV) properly before power-off. Also affects: needforheat-presence-detector-firmware, needforheat-living-room-module-firmware. *(Trello #860, #862, #870, #686, #996, #822, #363)*
- [ ] <a id="led"></a>**LED feedback on devices without a screen.** Simple LED patterns for heartbeat, activation success and fresh battery, for devices without e-ink. *(Trello #202)*
- [ ] <a id="upload"></a>**Spread uploads and make them smaller.** With buffering, many devices will upload at the same moment; pick a random moment within the upload window. Consider sending property IDs instead of names, or compressing the JSON. Also affects: needforheat-server-api. *(Trello #497, #659)*
- [ ] <a id="config"></a>**All device-type settings in platformio.ini.** Device type name, property names and intervals scattered over the code; move them to build flags so README tables and code stay consistent. Document which flags must be set per lab or campaign. Consider making these settings deploy-time (for example in NVS, set while flashing from the browser) instead of build-time, so deployers need no IDE. Also affects: needforheat-p1-reader-firmware, needforheat-presence-detector-firmware. *(Trello #695, #510)*
- [ ] <a id="serverselect"></a>**Let the app tell the device which server to use.** Today the server hostname is a build flag. Optionally pass test/production (or a hostname) during provisioning, so one firmware image serves all. Sending extra data from app to device during provisioning is unusual but justified here; the same channel could later carry a nonce for device attestation. Also affects: needforheat-gearup-app. *(Trello #588, #292, #587)*
- [ ] <a id="softap"></a>**Provisioning via SoftAP.** Support Wi-Fi SoftAP provisioning next to BLE, for phones or devices where BLE is a problem. Also affects: needforheat-gearup-app. *(Trello #302, #112)*
- [ ] <a id="presence-other"></a>**Presence detection on hardware other than the CoreInk.** Also affects: needforheat-presence-detector-firmware. *(Trello #829)*
- [ ] <a id="partitions"></a>**Partition table without OTA.** Offer a layout that drops the OTA slots and gives the space to data (useful for buffering). *(Trello #569)*
- [ ] <a id="stress"></a>**Shorter intervals for STRESS_TEST builds.** *(Trello #830)*
- [ ] <a id="security"></a>**Security research: proof of possession and device trust.** Ideas to evaluate: a time-based one-time proof of possession instead of a fixed one, attestation of firmware before it joins the home network, a secure element (ATECC608B), and secure boot on the CoreInk. No shared secret on the device: one leaked secret would compromise all devices, and a per-device secret complicates logistics. Explore a device signature combined with time; mind relay attacks via a stolen genuine device. Also affects: needforheat-gearup-app, needforheat-server-api. *(Trello #307, #868, #308, #326, #461)*

Also affects: needforheat-server-api, needforheat-gearup-app, needforheat-manuals, needforheat-manual-server, needforheat-server-configuration, needforheat-p1-reader-firmware, needforheat-living-room-module-firmware, needforheat-presence-detector-firmware, needforheat-boiler-monitor-firmware. *(Trello #1030)*
