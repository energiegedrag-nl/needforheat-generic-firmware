# TODO – needforheat-generic-firmware

Open work for this repository, distilled from the earlier NeedForHeat backlog at Windesheim, including the discussions on it (paraphrased and regrouped), and from the 2026 maintenance review.

Items that touch several repositories are written out in full in one *lead* repository; the others list them with a link (→). Keep the details up to date in the lead repository only.

## Now: needed to run at home this winter

- [ ] <a id="buffer"></a>**Field-test the persistent measurement buffer.** Built in v3.4.0-rc (#14): a power-loss-safe ring log (FlashLog) on data partition `nfhbuf`, with RAM as fallback when a device has no such partition. The living room module has the partition (128 KiB, about 3 days). Still to do: test on hardware (pull the plug and switch off Wi-Fi for a day, check nothing is lost or duplicated), add the partition to the P1 reader, presence detector and boiler monitor, and size it per device. A new partition table only takes effect after a USB flash. LittleFS was considered and is heavier than needed for one queue. Also affects: needforheat-server-api.
- [ ] <a id="unsigned"></a>**Release workflow without the Windesheim signing key.** The release workflow assumes a secure-boot signing key that this organisation does not have. Make signing optional so unsigned releases (and OTA images) can be built here. Also affects: needforheat-p1-reader-firmware, needforheat-living-room-module-firmware, needforheat-presence-detector-firmware, needforheat-boiler-monitor-firmware.
- [ ] <a id="actfail"></a>**Recover cleanly when activation fails.** If Wi-Fi provisioning succeeds but activation at the server fails, the device looks provisioned but never uploads. v3.3.0 retries by restarting every 60 s; better: after a few failures, clear the Wi-Fi credentials and show the provisioning QR code again, with a clear message. Since v3.4.0-rc the screen shows the error with a status code and the server; the device still restarts every 60 s. Also affects: needforheat-living-room-module-firmware.
- [ ] → Hardware test of v3.4.0 on the living room module — see [needforheat-living-room-module-firmware](https://github.com/energiegedrag-nl/needforheat-living-room-module-firmware/blob/main/TODO.md#hwtest)

## Soon: robustness and correctness

- [ ] <a id="ota"></a>**Make OTA updates trustworthy and staged.** OTA is implemented but has never been tested end to end. Test it on the P1 reader and living room module first. Then replace the poll of the GitHub API (60 calls/hour per IP, every device updates at once) by an update channel on our own server with staged rollout (a few devices first, then the rest). Expected to be little work for the P1 reader and living room module. Keep a manual step before a release reaches devices (suggestion from the team). Use the certificate bundle and enable app rollback (no eFuses involved; needs one USB flash for the new bootloader). Also affects: needforheat-server-api, needforheat-p1-reader-firmware, needforheat-living-room-module-firmware.
- [ ] <a id="idf"></a>**Upgrade to ESP-IDF 5.5 (WPA3, Wi-Fi 6).** The firmware is built on ESP-IDF 4.2, which cannot join WPA3-only or some Wi-Fi 6 networks. Plan and spike results: [needforheat-generic-firmware#4](https://github.com/energiegedrag-nl/needforheat-generic-firmware/pull/4) (LovyanGFX 1.x, NVS types, OTA config, SNTP and Bluetooth API changes). Real impact: at least one participant dropped out because their network used WPA3 or WPA2-Enterprise, and some phone hotspots were not visible. Library choices: ESP-IDF 5.5 first, written against APIs that 6.0 keeps (component `network_provisioning` instead of the built-in `wifi_provisioning`, new I2C driver, `esp_sntp_*`); M5GFX for the e-ink screen; NimBLE for devices that use Bluetooth only for provisioning; `sdkconfig.defaults` per device instead of full `sdkconfig` files. Also affects: needforheat-gearup-app, needforheat-p1-reader-firmware, needforheat-living-room-module-firmware, needforheat-presence-detector-firmware, needforheat-boiler-monitor-firmware.
- [ ] <a id="skew"></a>**Log clock skew after every NTP sync.** Report how many seconds the clock was corrected at each NTP sync as property `clock_skew` (register it for each device type). Cheap to add and lets the analysis detect and repair bad timestamps. Data from the earlier campaign had 7 uploads dated 1970 and 1390 uploads dated 2036 or later; comparing device time with server time per upload makes such errors detectable. Also affects: needforheat-server-api.
- [ ] <a id="interval"></a>**Find out why some 10-minute series contain 20-minute gaps.** About 3% of the intervals in 10-minute schedules were 20 minutes. Find the cause (scheduler drift, upload blocking measurements, Wi-Fi reconnects) and fix it.
- [ ] <a id="buttons"></a>**Let generic and device-specific code share buttons.** When device firmware uses a button the generic library already registered, presses get lost. Provide one button registry with per-button handlers. Also affects: needforheat-p1-reader-firmware, needforheat-living-room-module-firmware, needforheat-presence-detector-firmware, needforheat-boiler-monitor-firmware.
- [ ] <a id="provint"></a>**Provisioning after a Wi-Fi reset fails if a measurement interrupts it.** On the living room module, provisioning after a Wi-Fi reset can be interrupted by a scheduled measurement; the result is a reboot, an unauthorized device and a misleading 'Info? Scan!' screen. Pause measurements while provisioning. Likely cause (hypothesis): a measurement alarm still set in the RTC after the Wi-Fi reset. Clear the BM8563 alarm (or re-initialise the RTC) when resetting provisioning, then test. Also affects: needforheat-living-room-module-firmware.
- [ ] <a id="einkstatus"></a>**Show device status on the e-ink screen.** After provisioning, show the time of the last measurement and the last successful upload (local time) and, while provisioning, which step the device is in, including failures. Optionally show current values (CO2, temperature, RH, persons; P1 power). Implemented in draft PR #16 (generic) and living room PR #8: provisioning steps, error screen, overview with CO2, temperature, humidity, clock, Wi-Fi, TEST badge and pending measurements. Still open: a tile with the number of people present (presence detection has no getter yet), P1 power on the P1 reader, test on the CoreInk. Also affects: needforheat-living-room-module-firmware, needforheat-p1-reader-firmware.
- [ ] <a id="crtbundle"></a>**Use the ESP-IDF certificate bundle.** Replace the pinned PEM files (`github_root.pem`, `isrg_root.pem`) by `esp_crt_bundle` (available since ESP-IDF 4.1), so uploads and OTA keep working when a root certificate changes. Also affects: needforheat-p1-reader-firmware, needforheat-living-room-module-firmware, needforheat-presence-detector-firmware, needforheat-boiler-monitor-firmware.

## Later: features and ideas

- [ ] <a id="refactor"></a>**Move shared code into this library (refactoring plan).** The plan, with its reasons and steps, is in [docs/developing/refactoring-plan.md](docs/developing/refactoring-plan.md): CI that builds every device against this library (step 1, done in #22), one version for all devices (first the latest v3 tag, v4 after the heating season), then I²C with configurable ports, a power manager for CoreInk BASEs and the e-ink screen layout. Also affects: needforheat-p1-reader-firmware, needforheat-living-room-module-firmware, needforheat-presence-detector-firmware, needforheat-boiler-monitor-firmware.
- [ ] <a id="bases"></a>**Power manager for CoreInk BASEs (P1-BASE v3, BatteryBASE).** Detect the BASE at run time, coordinate chargers (at most one BASE charges; total below ≈ 0.5 C of the 390 mAh cell), estimate state of charge and remaining hours, warn on the screen, upload the values. Moves the P1-BASE charging control out of the P1 reader. Hardware: [needforheat-p1-base-hardware](https://github.com/energiegedrag-nl/needforheat-p1-base-hardware) (design-v3.md § 4.5) and [needforheat-battery-base-hardware](https://github.com/energiegedrag-nl/needforheat-battery-base-hardware) (design brief). Also affects: needforheat-p1-reader-firmware, needforheat-living-room-module-firmware.

- [ ] <a id="rtcprep"></a>**Set the RTC while preparing devices.** Devices can start measuring before NTP has synced. Set the RTC to UTC right after flashing (for example from the flashing tool), so early measurements get a usable timestamp. v3.3.0 already drops implausible timestamps. The BM8563 RTC has a voltage-low flag that tells whether its time is still valid; use that instead of (or besides) the year check in v3.3.0.
- [ ] <a id="infourl"></a>**Default and server-provided info link on the screen.** API v3 no longer returns `device_type.info_url`; v3.3.0 keeps the built-in default. Decide whether the server should provide the link and text again (per device type or campaign), and make the default point to our own manuals. Decided earlier: the text under the QR code stays language-neutral ('Info? Scan!'); the link first tries a campaign-specific page and falls back to a generic default page that the firmware developer writes. Also affects: needforheat-server-api.
- [ ] <a id="einkfix"></a>**E-ink screen glitches.** Speed up drawing multi-line menus (off-screen buffer); fix text shifting up after a menu times out; keep the screen readable after power loss instead of going white or dim; honour the 4-module quiet zone around QR codes; check whether `epd_fast` is still needed with LovyanGFX 1.x. Known remedy for fading: switch the e-paper charge pump (HV) properly before power-off. Draft PR #16 draws every screen off-screen (1-bit sprite) and chooses fast or full refresh, puts the panel to sleep before power-off and adds a quiet zone around QR codes. Still open: the pre-provisioning power-off timeout (`power_off_timeout.cpp`) cuts power without `PrepareForPowerOff()`; move to M5GFX or LovyanGFX 1.x with the ESP-IDF upgrade. Also affects: needforheat-presence-detector-firmware, needforheat-living-room-module-firmware.
- [ ] <a id="led"></a>**LED feedback on devices without a screen.** Simple LED patterns for heartbeat, activation success and fresh battery, for devices without e-ink.
- [ ] <a id="upload"></a>**Spread uploads and make them smaller.** With buffering, many devices will upload at the same moment; pick a random moment within the upload window. Consider sending property IDs instead of names, or compressing the JSON. Also affects: needforheat-server-api.
- [ ] <a id="config"></a>**All device-type settings in platformio.ini.** Device type name, property names and intervals scattered over the code; move them to build flags so README tables and code stay consistent. Document which flags must be set per lab or campaign. Consider making these settings deploy-time (for example in NVS, set while flashing from the browser) instead of build-time, so deployers need no IDE. Also affects: needforheat-p1-reader-firmware, needforheat-presence-detector-firmware.
- [ ] <a id="softap"></a>**Provisioning via SoftAP.** Support Wi-Fi SoftAP provisioning next to BLE, for phones or devices where BLE is a problem. Also affects: needforheat-gearup-app.
- [ ] <a id="presence-other"></a>**Presence detection on hardware other than the CoreInk.** Also affects: needforheat-presence-detector-firmware.
- [ ] <a id="partitions"></a>**Partition table without OTA.** Offer a layout that drops the OTA slots and gives the space to data (useful for buffering). v3.4.0-rc keeps both OTA slots (0x1e0000 each) and adds a 128 KiB buffer partition on the living room module.
- [ ] <a id="stress"></a>**Shorter intervals for STRESS_TEST builds.**
- [ ] <a id="security"></a>**Security research: proof of possession and device trust.** Ideas to evaluate: a time-based one-time proof of possession instead of a fixed one, attestation of firmware before it joins the home network, a secure element (ATECC608B), and secure boot on the CoreInk. No shared secret on the device: one leaked secret would compromise all devices, and a per-device secret complicates logistics. Explore a device signature combined with time; mind relay attacks via a stolen genuine device. Concrete next steps that do not lock the device: provisioning security 2 (SRP6a; the device stores only a verifier), app rollback, and signed updates without hardware secure boot (check first that nothing is written to eFuses). Secure boot and flash encryption stay off for now. Also affects: needforheat-gearup-app, needforheat-server-api.

Also affects: needforheat-server-api, needforheat-gearup-app, needforheat-manuals, needforheat-manual-server, needforheat-server-configuration, needforheat-p1-reader-firmware, needforheat-living-room-module-firmware, needforheat-presence-detector-firmware, needforheat-boiler-monitor-firmware.
